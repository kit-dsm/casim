# OOBP archive versus local Henn sources

The 16 local `abc1` Heßler-Irnich files and the original `abc1` archive files are different representations and different position data. This comparison is reproducible with `python scenarios/scenario_henn_online/scripts/compare_henn_sources.py`. The archive doubles each physical aisle into left/right IDs (0–19); the script maps them to physical aisle 0–9 and side and compares its location `l` with local cell `44-l`. This orientation aligns the first item of the first order; it is a comparison convention, not an assertion about the archive coordinate origin. Counts use multisets, so duplicate lines remain visible. `x/y matched` means the two whole-instance position multisets share x of y original lines. `orders match positions` compares each order separately.

The archive order files have no header. Its `settNN.txt` files carry layout and instance settings. Shared values agree on 10 aisles, 45 cells, 40/60/80/100 orders and picker capacity 30/45/60/75 (`m_no_a_p_b`); the local header adds explicit layout distances, a depot, article and SKU sections. The archive settings do not specify a depot. The [benchmark page](https://grafo.etsii.urjc.es/optsicom/oobp.html) says the Henn depot is bottom left. The local header says aisle 0, bottom. The arrival CSV contents are byte-identical for all 16 pairs, although the archive uses a different prefix and one shortened filename in the 100-order group.

All 16 pairs have the same number of order lines and the same line count for every corresponding order, but their item positions and order membership by position differ:

The other 48 archive instances (`abc2`, `ran1`, `ran2`) have no local counterparts. All 64 original order files, 64 settings files, 64 arrival CSVs, plus the archive Henn README and description PDF, are preserved under `data/oobp/`. File-level SHA-256 hashes are in `data/oobp/SHA256SUMS.txt`.

The existing `HennOnlineLoader` cannot read these original files: it requires the Heßler-Irnich `ARTICLE_SECTION`, `SKU_SECTION`, `ORDER_SECTION` and explicit geometry/depot header, while the archive has separate `settNN.txt` settings and `Order N`/`Aisle`/`Location` records. It also constructs only `Arrival_Time_abc1_<stem>.csv`, which misses the archive naming for all groups and the 100-order `abc1` files. An OOBP reproduction needs an archive-format parser, settings-to-layout mapping, and robust arrival-file matching. This is deferred to Task 6.0; this phase leaves scenario behavior unchanged.
